测试计划编辑器 + 不可变执行快照 MVP 实现报告

在三引擎接入、任务控制、报告中心、环境与资源配置中心之上，让用户以受控表单创建 / 编辑 / 复制 / 预检由 pytest、Locust、MatchEval 步骤组成的测试计划；计划只引用 Environment / Executor / AssetSource 的 ID/key；每次执行固化不可变的计划版本与计划快照。

只管理 计划/执行/报告/配置 不做用例编辑器 / 脚本在线编辑 / 拖拽大屏 不做鉴权 / 多租户 / 分布式调度 不擅自填入或连接真实 Colyseus/Unity/识别资产 不落明文密钥与绝对路径

1. 计划数据模型与迁移

计划由 plans（计划定义）与 plan_runs（每次执行的固化快照）两张表承载；迁移增量、非破坏，旧库启动即自动升级，不重建、不改写历史行。

表结构变更

表新增列语义
plansrevision INTEGER DEFAULT 1计划版本号；创建为 1，每次用户编辑 +1
planscreated_at / updated_at创建 / 最近更新时间戳（既有列，编辑器展示）
plan_runsplan_revision INTEGER执行时固化的计划版本号（可空）
plan_runsplan_snapshot TEXT执行时固化的完整计划快照 JSON（可空）

迁移策略

  • 只补列、不重建：db.init_db 用 PRAGMA table_info 检测缺失列后 ALTER TABLE … ADD COLUMN；旧 plans 行补 revision 默认 1，旧 plan_runs 行 plan_revision/plan_snapshot 保持 NULL。
  • 不伪造历史：缺新字段的历史执行记录一律留空（NULL），不填充、不猜测；报告索引侧沿用既有 metadata_incomplete=1 降级标记。
  • 版本号不被迁移污染：预置与旧库回填调用 db.update_plan(..., bump_revision=False)，仅用户编辑才递增 revision；预置计划初始 rev=1。
  • 兼容读取：_plan_row 把 revision 归一为整数（缺省 1）；_run_row 把 plan_snapshot JSON 字符串解析为字典，非法 JSON 视作无快照、不阻断历史读取。
快照职责划分（互不重复泄露）：plan_runs.plan_snapshot 只含计划定义（名称 / 版本 / 引用 ID / 步骤与白名单参数 / fail_fast / 非敏感指纹）；jobs.config_snapshot 只含环境 / 执行机 / 资产的脱敏视图与指纹。两者都只保留受控 ID/key 与脱敏信息，绝不落明文密钥或绝对路径。

2. 计划编辑器交互

新增路由 #/plan-editor/{id}（新建用 new）。计划列表页提供：一键执行、预检、编辑、复制、新建计划。

新建 / 编辑

受控表单填写基础信息与步骤；编辑已保存计划时展示 rev 与 created_at/updated_at，每次保存 revision +1。

复制

POST /api/plans/{pid}/copy 生成独立副本：revision 重置为 1，名称可显式指定（默认「X (副本)」）；复制仍需通过引用 / 步骤校验，编辑副本不影响源计划。

查看版本信息

编辑器头部与基础信息卡展示 rev / 创建 / 更新；执行详情展示当次固化的 plan_revision。

一键执行

「保存并执行」保存后触发，进入对应 PlanRun 详情；执行列表页也可一键执行。

基础字段

名称、说明、Environment、Executor、AssetSource、fail_fast（失败即停）。下拉项只来自启用的配置实体；AssetSource 按步骤引擎类型过滤（仅展示 locust / matcheval 兼容项）。

步骤管理

  • 支持新增 / 删除 / 上移 / 下移；默认串行执行，顺序即列表顺序。
  • 每个步骤引擎只能是 pytest / locust / matcheval 三种已注册引擎；切换引擎后旧参数不再适用，自动重置。
  • 每步骤可选 requires_exclusive（独占执行机，UI/Unity 类）与 timeout_sec。
  • 不实现删除计划，避免误删仍被历史记录引用的计划。

3. 三引擎表单字段与白名单

每种引擎使用专用表单字段与后端白名单；前端不提供任意 JSON / 命令 / 路径 / 解释器输入框。前端校验只改善体验，后端是唯一可信校验边界（validate_step_params 对非白名单键一律拒绝）。

引擎允许参数键约束
pytest args · cwd/cwd_root · timeout_sec · asset_source_id args 仅允许相对测试选择器 / 开关（如 demo/test_platform_demo.py -o addopts= --tb=short）；拒绝绝对路径、盘符（C:）、..、shell 元字符（; | & $ ` < > \）与 .exe。cwd/cwd_root 必须是受控工作目录根 key。
locust locustfile · users · spawn_rate · run_time · csv_full_history · timeout_sec · asset_source_id locustfile 必须是受控场景引用 key（http-fixture / colyseus-bot）；users/spawn_rate/timeout_sec 为整数；run_time 为时长串（如 15s/1m）。
matcheval dataset · algorithm · threshold · output_level · timeout_sec · asset_source_id dataset 必须是受控 dataset 引用 key（fixture-small / fixture-empty）；algorithm 白名单 tpl | mstpl | kaze | brisk | akaze | orb；threshold 必须是 0..1 的数字；output_level 只能是 full | summary。
安全边界：拒绝未注册引擎（如 shell）、拒绝任意命令型参数键（如 command）、拒绝绝对路径 / shell 元字符 / 可执行文件 / 非受控 cwd_root / 非受控 locustfile / 非受控 dataset / 越界或非数值 threshold / 非白名单 algorithm / 非法 output_level / 空步骤。仅启用的 Environment / Executor / AssetSource 可被引用（只认 ID）。

4. 计划预检 / 执行预览

两个入口复用同一套后端校验逻辑：POST /api/plans/precheck（草稿，不落库）与 POST /api/plans/{pid}/precheck（已保存）。不创建 PlanRun、不创建 Job、不拉起子进程、不发起压测或完整测试。

5. 快照不可变性与职责划分

触发计划时，后端先 build_plan_snapshot(plan) 固化「执行时的计划定义」，再 db.create_run(plan_revision, plan_snapshot) 写入 PlanRun；已创建 PlanRun 的计划结构、步骤参数、fail_fast、配置引用不因后续编辑 Plan 而改变。

固化内容
名称、说明、revision、引用 ID（Environment/Executor/AssetSource）、步骤（顺序/引擎/名称/独占/参数）、fail_fast、owner、snapshot_fingerprint
指纹
_h("plan", plan_id, revision, steps_json, env_id, exec_id, asset_id, fail_fast) —— sha256 前 12 位，非敏感、稳定
Job 快照
jobs.config_snapshot（环境/执行机/资产脱敏视图与指纹）在 Job 创建时同样固化，与 PlanRun 快照互补

不可变性验证（verify_plan_editor.py 场景 8 + 单测）

  1. 创建计划 PE-snap-A（pytest→locust，fail_fast=true）并执行 → PlanRun 固化 plan_revision=1 与完整 plan_snapshot，带非敏感指纹。
  2. 随后编辑原计划：改名、换步骤（改为单步 matcheval）、关 fail_fast、换 AssetSource 引用 → 原计划确已变为 rev=2 且定义变化。
  3. 再次读取历史 PlanRun → plan_revision 仍为 1、plan_snapshot 名称/步骤/fail_fast 不变、snapshot_fingerprint 一致。
  4. 历史 Job 的 config_snapshot.snapshot_fingerprint 不漂移；执行列表与报告中心的计划名均取自执行时快照（后续改名不漂移）。
报告联动：历史报告 / 对比使用执行时快照（PlanRun 计划快照 + Job 配置快照），不读取当前 Plan 定义；从编辑器触发后进入 PlanRun 详情，展示当次 plan_revision 与只读 plan_snapshot。

8. 如何创建第一份真实三引擎计划

平台不擅自配置、连接或压测真实环境；凭据只登记引用名，不存明文。按以下步骤录入后即可在 Web 内创建并预检真实三引擎计划：

  1. 录入真实被测环境（Environment）：新增 kind=colyseus/http 环境，填 host / port / 协议；如有鉴权，只登记环境变量名或外部 secret 引用名，绝不填明文；点预检确认 TCP 连通。
  2. 登记真实 Locust 场景与识别资产（受控 key）：把真实 locustfile 登记为受控场景引用；把真实 dataset / 模板目录 / 场景目录 / 真值约定登记为受控引用；Airtest-master 目录经 PLATFORM_AIRTEXT_DIR 或受控引用登记。
  3. 配置执行机（Executor）：选择具备 pytest + locust + cv2 + numpy 的解释器引用（如 locust-venv / 三引擎专用执行机），选择受控 cwd_root，allowed_runners 勾选 pytest/locust/matcheval；点预检确认解释器与依赖就绪。
  4. 建立资产源（AssetSource）：新增 kind=matcheval（引用上一步登记的 dataset / Airtest 目录）与 kind=locust（引用受控场景）；点预检确认资产结构完整。
  5. 新建计划：在「测试计划」页点「新建计划」，填名称 / 说明，选择上述 Environment / Executor / AssetSource，按需勾选 fail_fast。
  6. 添加三个步骤：pytest（相对测试选择器 + 受控 cwd_root）→ locust（受控场景 + users/spawn_rate/run_time）→ matcheval（受控 dataset + 白名单 algorithm + threshold + output_level）；用上移/下移调整串行顺序。
  7. 预检 / 执行预览：点「预检 / 执行预览」，确认 ok=true、missing 为空、无独占锁占用、fail_fast 行为符合预期。此步不产生任何副作用。
  8. 保存并执行：点「保存并执行」进入 PlanRun 详情，查看当次固化的 plan_revision 与只读 plan_snapshot；随后在报告中心按引擎筛选查看三引擎报告，同配置两两对比。
当前隔离环境下，三引擎 fixture 链路已全绿（三引擎专用执行机 + locust-fixture 环境 + matcheval fixture 资产），verify_plan_editor.py 场景 9 已实跑 pytest→locust→matcheval 组合计划并聚合为 success。但真实 Colyseus/Unity 环境、真实 Locust 场景与真实识别资产尚未录入，因此真实业务趋势须待上述信息录入并预检通过后方可产生。
