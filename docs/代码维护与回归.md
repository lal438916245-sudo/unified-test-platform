# 平台代码维护与回归

## 代码边界

平台运行代码位于 `backend/app/`、`backend/run.py`、`backend/preset.py`、
`backend/platform_ui_guard.py` 和 `frontend/`。`backend/tests/`、`_ci/`、
`_v0.3_baseline/` 验证平台本身。

工作区中的 GameAutoTest-Pro、Colyseus-Storm、match_eval.py 和真实游戏项目是
独立的测试工程、评估工具或被测应用，不应随平台的整理一起修改。

## 共享逻辑的入口

| 模块 | 职责 |
|---|---|
| `backend/app/api/router.py` | 用例、套件、计划、执行与报告接口；组合资源接口 |
| `backend/app/api/configuration.py` | 环境、执行机、资产、UI 设备、公共运行要求及预检接口 |
| `backend/app/api/payloads.py` | 三类资源的字段过滤、创建默认值、部分更新与数值转换 |
| `backend/app/executors/base.py` | 子进程启动设置、注册、日志读取、取消与回收工具 |
| `backend/app/executors/junit.py` | pytest/UI 共用的 JUnit 解析与结果构建 |

Runner 负责自己的命令、环境变量、产物和清理顺序。公共启动函数只合并相同的
`Popen` 设置，不合并各引擎不同的取消、清理或报告处理。

`PytestRunner` 保留原有结果处理方法；自定义解析或产物方法继续通过这些方法调用。

## 行为保真约定

- 保持 HTTP 路径、参数、响应、错误文案、状态码及路由顺序。
- 部分更新中，未提交的字段不补默认值；显式 `None` 继续按现有规则剔除。
- 创建执行机时继续写入旧表要求的空 `python_executable` 和 `cwd` 列。
- 新建默认列表独立分配，避免多个配置共享同一个列表。
- 表单展示与参数保真合并共用 `PL_DEFAULTED`；保留“未填写”与“明确设置”的区别。
- 表单清空后的读取兜底与 Runner 的执行默认值分别保留。例如 Locust 表单默认
  users=5、run_time=15s，Runner 缺省 users=10、run_time=20s。统一代码位置不意味着
  可以调整这些既有取值。
- 保留旧步骤未管理字段、引用版本、内容指纹、历史快照和原始报告。
- 保存、预检、执行前的校验各有时效要求，不因看起来重复而删除。
- 接口拆分后，测试的 monkeypatch 应指向函数实际定义的模块；原断言继续保留。

## 代码风格

`pyproject.toml` 统一 Python 的 100 列格式、Python 3.11 目标语法和导入排序。
Black、Ruff 只作为已有开发工具使用，没有加入平台依赖声明。

格式整理使用 Black 的 AST 等价检查；运行入口的延迟导入是有意保留的例外：
必须先处理 CLI 隔离参数，再导入读取数据目录的 scheduler。

## 回归命令

在平台目录执行：

```powershell
python -B -m pytest backend/tests -q -o addopts=
python -B _ci/l1_smoke.py
```

L1 使用动态端口、临时数据库，并显式传入 `--seed-demo`，完成启动、预检、执行、
报告和进程清理验证；普通平台启动仍默认空白配置。

本机已有 Ruff/Black 时，可检查运行代码与新增契约测试：

```powershell
python -B -m ruff check backend/app backend/run.py backend/preset.py backend/platform_ui_guard.py backend/tests/test_refactor_contracts.py
python -B -m black --check backend/app backend/run.py backend/preset.py backend/platform_ui_guard.py backend/tests/test_refactor_contracts.py
```
