# 新项目登记与执行

操作顺序：**准备项目 → 登记项目与 Python → 关联执行机 → 登记入口 → 创建用例和计划 → 预检执行**。已有测试项目可通过网页接入。

## 1. 准备项目

在运行平台的电脑准备好：

- 测试源码、配置和资产文件。
- 项目 Python 环境及依赖。当前运行环境检查包含 `pytest`，其他引擎还需各自依赖。
- 所需的被测服务、数据库或客户端，确认可以独立启动。

登记功能不会自动安装依赖或部署被测服务。新电脑上的虚拟环境应重新创建。

## 2. 登记项目

打开 **资源与环境 → 管理项目与测试入口 → 新增项目**：

| 字段 | 填写内容 |
|---|---|
| 项目名称 | 易于识别且不重复的名称 |
| 本机项目根目录 | 当前电脑上已存在的项目完整目录 |
| 项目备注 | 可留空 |
| 启用项目 | 勾选 |

点击 **保存项目**，再点击项目行的 **检查配置**。

pytest / UI 项目可点击 **发现 pytest / UI 用例 → 填入登记表**。发现只读取源码，不运行测试；填入后仍需保存入口。其他类型手动登记。

## 3. 登记 Python 并关联执行机

在同一页面点击 **新增运行环境**：

| 字段 | 填写内容 |
|---|---|
| 运行环境名称 | 可识别用途的名称 |
| 本机 Python 解释器 | Python 完整路径；虚拟环境通常为项目下的 `.venv\Scripts\python.exe` |
| 补充依赖模块（逗号分隔） | 需要检查的导入模块名，无补充项可留空；不填 pip 命令 |
| 启用条目 | 勾选 |

点击 **保存运行环境 → 检查配置**。缺少依赖时，在这个 Python 环境安装后重新检查。

通过后点击该行 **关联执行机**：

| 字段 | 填写 / 选择 |
|---|---|
| 名称 | 执行机名称 |
| Python 解释器引用（受控） | 刚登记的运行环境 |
| 允许工作目录根（受控） | 刚登记的项目 |
| 并发槽位 | 首次使用保持 `1` |
| 允许的 Runner | 勾选实际使用的引擎，取消不需要的默认选项 |
| 启用 | 勾选 |

保存后，在 Executor 列表点击 **预检**。并发槽位属于任务执行配置，Locust 用户数在用例中设置。

## 4. 登记测试入口或资产

返回 **管理项目与测试入口 → 测试入口与资产 → 新增测试入口**，填写入口名称、类型、所属项目，勾选启用。

| 类型 | 入口 / 资产填写方式 |
|---|---|
| `pytest` | 项目内相对 Python 文件，可追加 `::类名::函数名` 或 `::函数名`；暂不登记单个参数化实例的 `[参数]` 选择器 |
| `airtest + Poco` | 项目内相对 UI Python 文件；按需勾选“需要被测服务” |
| `locust` | 项目内相对 Locust 脚本路径 |
| `matcheval 资产` | 模板目录、场景目录、兼容 match_eval 的脚本路径；可选填 Airtest 源码根 |

pytest、airtest、locust 入口相对于项目根目录填写，不填绝对路径、启动命令或 `..` 越界路径。视觉脚本和图片目录支持项目内相对路径或本机绝对路径。

点击 **保存测试入口 → 检查配置**。

## 5. 配置运行资源

返回 **资源与环境**，按需要配置：

- **在线服务**：新增 Environment，填写真实被测服务的类型、协议、host 和端口。host 不带协议、端口或路径。
- **离线评估**：新增类型为 `offline` 的 Environment。
- **UI 测试**：登记 UI 设备，关联允许 `airtest` 的执行机，配置窗口规则和 Poco 连接；按需登记公共运行要求。
- **资产源**：需要显式绑定资产时新增 AssetSource，选择与入口匹配的引用。

UI 脚本需按 `platform_poco` fixture 约定接入。视觉脚本需兼容 match_eval CLI / CSV 格式，图片真值遵循 `tpl_{id}_{scene}.png` / `scene_{scene}.png` 命名约定。

标准 Locust HTTP 请求使用计划目标地址；自行创建的 HTTP / WebSocket 连接需在脚本中适配目标配置。

## 6. 创建用例和计划

1. 打开 **测试用例 → 新建用例**，填写名称，选择对应引擎。
2. 选择刚登记的入口 / 场景 / 数据集，填写参数和超时后保存。UI 用例还需选择设备。
3. 打开 **测试计划 → 新建计划**，填写名称，选择 Environment、Executor，按需选择 AssetSource。
4. 点击 **添加用例步骤**，选择刚保存的用例，核对参数、顺序和超时后保存。

多个用例需要复用顺序时，可先创建测试套件，再插入计划。首次验证建议只运行一个用例；Locust 先使用少量用户和较短时长。

## 7. 预检与验收

1. 启动依赖服务；UI 测试还需启动客户端并恢复初始状态。
2. 在计划列表点击 **预检**，修复失败项后重新检查。
3. 点击 **一键执行**，进入执行详情查看日志。
4. 结束后打开报告，确认实际执行了测试、统计符合预期、所需产物可打开。

登记检查通过只表示配置有效，业务是否成功以本次日志、断言和报告为准。后续日常操作参照 [平台使用说明](平台使用说明.md)。
