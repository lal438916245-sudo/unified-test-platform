# 平台使用说明

平台用于管理测试用例、组合执行步骤、运行测试、查看日志和报告，支持 pytest、Locust、Airtest + Poco、MatchEval 四类引擎。

首次使用先阅读 [安装与配置迁移](安装与配置迁移.md)，接入项目参照 [新项目登记与执行](新项目登记与执行.md)，移动目录参照 [换电脑与路径配置](换电脑与路径配置.md)。

## 1. 启动与停止

1. 在平台的 `platform` 目录运行 **start.bat**。
2. 浏览器打开 <http://127.0.0.1:8000>。
3. 停止前等待测试结束，在启动终端按 `Ctrl+C`。

端口占用时，在 `platform` 目录的 PowerShell 中执行：

```powershell
.\start.ps1 -Port 8001
```

然后访问 <http://127.0.0.1:8001>。修改端口不会隔离数据，独立数据目录的设置见安装文档。

## 2. 页面与用途

| 页面 / 对象 | 用途 |
|---|---|
| 测试用例 | 保存测试入口、引擎和默认参数，供多个计划复用 |
| 测试套件 | 将多个已保存用例按顺序组合 |
| 测试计划 | 选择被测环境、执行机和步骤，发起执行 |
| 报告中心 | 查结果、日志、产物，对比两次执行 |
| 资源与环境 | 管理项目、Python、被测地址、执行机、设备和资产 |
| 安装与配置迁移 | 导出或导入用例、套件和计划定义 |

一次计划执行称为 **PlanRun**；其中每个步骤的一次执行尝试称为 **Job**。报告按 Job 展示。

## 3. 配置资源

打开 **资源与环境**，按需配置：

| 配置项 | 操作与填写要点 |
|---|---|
| 项目与测试入口 | 点击“管理项目与测试入口”，登记本机目录、Python 和脚本，保存后点击“检查配置” |
| Environment | 新增被测环境，填写类型、协议、目标 host 和端口；host 只填 IP 或域名；离线评估选择 `offline` |
| Executor | 选择 Python 解释器引用、允许工作目录根和允许的 Runner，启用并保存，再点击“预检” |
| UI 设备 | 关联允许 `airtest` 的执行机，填写窗口规则、Poco 地址和端口，保存后实时探测 |
| 公共运行要求 | 选择适用 UI 套件，按需补充依赖和检查要求，供同类用例复用 |
| AssetSource | 需要明确绑定资产时创建，类型和引用应与场景、UI 套件或视觉数据集一致 |

Python 依赖应提前安装到所选执行机的解释器中。“补充依赖模块”填写导入模块名，不填写安装命令。Environment 中的 secret 字段填写引用名，不填写密码。

路径和 `localhost` 均属于运行平台的电脑。当前 Executor 用于选择本机执行配置，不提供远程执行机管理。

## 4. 创建测试用例

1. 打开 **测试用例 → 新建用例**。
2. 填写名称，选择引擎，按下表配置。
3. 设置超时，点击 **保存**。

| 引擎 | 需要选择 / 填写 |
|---|---|
| `pytest` | 已登记 pytest 入口；自定义选择器时选择工作目录根，填写项目内相对选择器和允许的参数 |
| `locust` | 场景、并发用户数、启动速率、运行时长；步骤超时应大于运行时长，留出启动和收尾时间 |
| `airtest` | UI 套件、已登记用例、目标设备、公共运行要求、等待超时；设备需属于计划使用的执行机 |
| `matcheval` | 样本集、算法、阈值和输出级别 |

“资产种类 asset_kind”可留空。被测环境、执行机和 AssetSource 在计划中选择。

项目中存在脚本、完成入口登记，都不会自动生成这里的用例记录。airtest 表单中的“UI 套件”用于选择登记的 UI 脚本，与导航中的“测试套件”不同。

## 5. 创建套件与计划

只有一个用例时，可直接创建计划。需要复用多个用例及其顺序时，先创建套件：

1. 打开 **测试套件 → 新建套件**，填写名称。
2. 选择用例，点击 **添加到末尾**，调整顺序后保存。

再创建计划：

1. 打开 **测试计划 → 新建计划**，填写名称。
2. 选择 **Environment** 和 **Executor**；按需选择兼容的 **AssetSource**。
3. 点击 **添加用例步骤**并选择用例，或选择套件后点击 **插入测试套件**。
4. 核对步骤顺序、参数和超时，按需勾选 **失败即停**。
5. 点击 **保存**。

步骤默认串行执行。**添加内联步骤**将参数直接保存在当前计划，不新增可复用用例。插入套件后，计划保存展开后的用例步骤；以后修改套件，已有计划不会自动更新。

## 6. 预检与执行

1. 启动测试所需的服务或客户端，准备好初始状态。
2. 在计划列表点击 **预检**；编辑中的计划可点击 **预检 / 执行预览**。
3. 查看失败项详情，修复后重新预检。“未检查”不代表通过。
4. 在列表点击 **一键执行**；需要先保存编辑内容时点击 **保存并执行**。
5. 进入执行详情，查看各 Job 状态和 **日志**。
6. 运行结束后打开 **报告**，核对统计和实际产物。

预检用于检查配置、依赖及当前资源状态，不执行完整业务测试。通过只代表检查时可用，执行时仍会重新检查。UI 测试需要自行启动客户端并准备初始页面。

| 状态 | 含义 / 下一步 |
|---|---|
| `queued` / `running` | 排队或执行中，可查看日志 |
| `cancelling` | 正在取消，等待回收完成 |
| `success` | 执行成功，继续核对报告与附加警告 |
| `failed` / `timedout` | 失败或超时，先看失败阶段和日志 |
| `cancelled` / `skipped` | 已取消或未执行 |
| `partial` | 整体执行仅部分完成，查看各步骤结果 |

运行中的 Job 可点击 **取消**。终态 Job 的 **重试**会新增尝试并保留旧结果；配置或脚本已变化时，应修正计划后新建执行。

## 7. 查报告与对比结果

1. 打开 **报告中心**，按计划、引擎、状态、环境和时间筛选。
2. 点击 **详情**查看结果、**日志**排查过程、**所属执行**返回执行详情。
3. 在报告内点击产物链接，打开或下载实际生成的文件。
4. 对比时分别选择一份 **基线**和一份 **候选**，点击 **进入对比视图**。

页面会检查引擎、环境和关键输入是否兼容。提示不可比较时，先核对两次配置。准备失败或取证失败时，部分截图、CSV、HTML 等产物可能不存在。

## 8. 更新、停用与归档

- **更新用例**：保存修改后检查引用它的套件和计划；引用过期时重新选择当前用例版本并保存，再预检执行。
- **更新套件**：如需让计划采用新成员或顺序，移除原步骤，再插入新版套件。
- **停用资源**：在对应编辑表单取消启用，已有引用和历史记录保留。
- **删除登记**：项目、运行环境和入口先点“查看引用”；有引用时使用停用。删除登记不会删除本机文件。
- **归档计划**：在列表点击“归档”，通过“已归档 → 恢复”重新使用。有未结束任务时先等待或取消完成。

## 9. 常见问题与备份

| 现象 | 处理方法 |
|---|---|
| 下拉框没有项目、入口或执行机 | 确认已保存、启用且类型兼容，重新打开表单 |
| 找不到 Python 或模块 | 核对执行机的 Python 引用，在该环境安装依赖后重新预检 |
| 被测服务不可达 | 核对服务状态、host、端口和网络；端口可连接仍需通过用例验证业务 |
| UI 窗口零匹配或多匹配 | 启动客户端，调整标题、进程或类名规则，确保唯一匹配 |
| Poco 连接失败或超时 | 核对客户端、SDK、地址和端口；Unity Editor 还需检查 Play 和暂停状态 |
| 任务提示配置或输入已变化 | 核对最新配置，重新预检并新建执行 |
| 有报告记录但附件打不开 | 确认数据目录的 `reports/`、`logs/` 已完整保留或迁移 |

默认数据在 `platform/data/`，包含 `db.sqlite`、`logs/`、`reports/`。备份前先停止平台，复制完整数据目录；项目源码、虚拟环境和外部资产另行备份。
