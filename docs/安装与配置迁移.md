# 安装与配置迁移

本篇说明首次安装平台，以及通过网页迁移用例、套件和计划。需要保留历史执行与报告时，参照 [换电脑与路径配置](换电脑与路径配置.md) 备份完整数据目录。

## 1. 首次安装

1. 在目标 Windows 电脑准备 **64 位 Python 3.11 或以上**。
2. 解压平台包，进入包含 `install.bat`、`start.bat` 的 `platform` 目录。
3. 运行 **install.bat**，等待成功。在线安装需要访问 Python 包源。
4. 运行 **start.bat**，浏览器打开 <http://127.0.0.1:8000>。
5. 新安装默认空白配置，按 [新项目登记与执行](新项目登记与执行.md) 登记本机资源。

安装器在平台目录创建 `.venv`，安装核心服务和 pytest。被测项目源码、项目依赖和被测服务需另行准备。

以下 PowerShell 命令均在 `platform` 目录执行。系统找不到正确 Python 时，指定已安装解释器的实际路径，替换命令中的路径：

```powershell
.\install.ps1 -PythonExe 'C:\Python\python.exe'
```

按需安装可选引擎依赖，参数也可组合：

```powershell
.\install.ps1 -WithUI
.\install.ps1 -WithLocust
.\install.ps1 -WithVision
```

这些参数将依赖安装到平台的 `.venv`。测试使用单独的项目 Python 时，还需在那个环境安装对应依赖，并在网页登记。

端口占用时执行 `.\start.ps1 -Port 8001`，访问 <http://127.0.0.1:8001>。停止平台使用启动终端中的 `Ctrl+C`。

## 2. 离线安装

先在有网络的电脑准备与目标 Python 版本及 Windows 架构匹配的依赖，将 `wheelhouse` 复制到目标平台目录：

```powershell
python -m pip download --only-binary=:all: -r requirements-core.txt --dest wheelhouse
```

需要可选引擎时，用对应的 `requirements-ui.txt`、`requirements-locust.txt` 或 `requirements-vision.txt` 重复下载到同一目录。下载所用环境应与目标环境匹配。

目标电脑执行，Python 路径替换为实际安装路径：

```powershell
.\install.ps1 -Offline -PythonExe 'C:\Python\python.exe'
```

使用可选引擎时同时添加对应的 `-WithUI`、`-WithLocust` 或 `-WithVision`。提示依赖缺失或 wheel 不匹配时，补齐匹配的依赖包后重新安装。

## 3. 导出定义

在原电脑打开 **安装与配置迁移 → 导出定义**：

1. 勾选要迁移的测试用例、测试套件或测试计划。
2. 点击 **导出选中项 JSON**，保存文件。
3. 提示引用过期时，先在套件 / 计划中更新用例引用，再重新导出。

| 会迁移 | 需要另外准备 |
|---|---|
| 用例参数、套件顺序、计划步骤与参数覆盖、启停和归档状态 | 项目源码、Python 环境、依赖、客户端、被测服务和资产文件 |
| 资源槽的名称和类型，供目标电脑重新关联 | 原电脑的实际路径、资源配置、密钥、历史执行、日志和报告 |

套件和计划引用的用例会自动包含。用例说明和参数会随定义导出，密码应通过专用配置引用使用。

## 4. 在目标电脑导入

1. 安装并启动目标电脑的平台。
2. 在 **资源与环境** 登记本机项目、Python、测试入口、执行机和被测环境；按需登记设备、公共运行要求和资产源。
3. 打开 **安装与配置迁移**，选择导出的 JSON，填写批次名称。
4. 点击 **导入到待关联批次**。
5. 为每个资源槽选择本机已登记资源；缺少资源时先去登记，再返回当前批次。
6. 按需填写“新增记录名称前缀”，点击 **保存关联并预览**。
7. 核对名称、数量、错误和警告，预览通过后点击 **确认新增这些记录**。
8. 到测试计划页面核对配置，先预检，再手动执行。

导入会新增记录，不覆盖已有记录；同名自动追加导入序号。导入和预览都不会运行测试。

## 5. 没有现成 JSON 时

少量用例可直接在网页创建，无需导入。需要批量编写时：

1. 点击 **下载 JSON 模板**或 **填入示例模板**。
2. 按模板修改资源槽、用例、套件和计划定义。
3. 按上节完成待关联批次、资源关联、预览和提交。

模板格式为 `unified-test-platform/config`，版本为 `1`；资源引用使用 `{"$resource":"资源槽ID"}`。Python 脚本通过测试入口登记；Excel、任意第三方 JSON 和数据库文件需另行转换，不能直接当作迁移 JSON 导入。

## 6. 继续导入与故障处理

| 情况 | 操作 |
|---|---|
| 尚未关联完成 | 在“导入批次”点击“关联 / 继续导入”，刷新或重启后可继续 |
| 不再导入 | 点击“放弃待导入批次”，正式记录不受影响 |
| 资源不匹配或不可用 | 更换关联或修复本机资源，再预览 |
| 提示预览过期 | 重新点击“保存关联并预览”，核对后提交 |
| 已提交后再次打开 | 查看原回执，正式记录在各自页面管理 |

导入提交整体成功或整体回滚，不会只留下半批记录。完成迁移后，仍需通过计划预检和实际执行验收。

## 7. 使用独立数据目录

需要隔离配置、日志和报告时，在 `platform` 目录执行：

```powershell
& '.\.venv\Scripts\python.exe' backend/run.py --data-dir '.\data-isolated' --port 8001 --no-browser
```

访问对应端口。仅更换端口仍使用原数据目录；备份恢复时以启动终端显示的数据目录为准。
