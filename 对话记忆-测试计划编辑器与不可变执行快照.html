1. 本次任务与总框架约束

目标：在已有「三引擎接入 + 任务控制 + 报告中心 + 环境与资源配置中心」之上，实现 MVP 的测试计划编辑器 + 不可变执行快照。用户可在 Web 中以受控表单创建、编辑、复制并预检测试计划；计划由 pytest、Locust、MatchEval 步骤组成，引用 Environment / Executor / AssetSource 的 ID/key；每次执行保存不可变的计划版本与计划快照。

硬约束（不得越界）：平台只管理计划、执行、报告、配置；不做用例编辑器 / 脚本在线编辑 / 拖拽大屏 / 鉴权 / 多租户 / 分布式调度；不擅自填入或连接真实 Colyseus/Unity/识别资产；不改写引擎算法逻辑；不新建独立报告页。

2. 关键决策

版本化计划

给 plans 加 revision，只有用户编辑才 +1；预置/迁移回填用 bump_revision=False，避免迁移污染版本号。

执行即固化

触发计划时先 build_plan_snapshot(plan)，再 create_run(plan_revision, plan_snapshot) 写入 PlanRun，实现「执行时的计划」不可变。

快照职责分离

plan_runs.plan_snapshot = 计划定义（名称/版本/引用 ID/步骤/fail_fast）；jobs.config_snapshot = 环境/执行机/资产脱敏视图。二者互补，均不含明文密钥与绝对路径。

后端为唯一校验边界

前端表单只改善体验；参数白名单、引用启用校验、预检全部在后端（validate_step_params / validate_plan_refs / precheck_plan）。

预检零副作用

预检复用执行校验，但不创建 PlanRun/Job、不拉子进程、不跑测试；返回 no_side_effects=true。

历史名不漂移

执行列表与报告中心的计划名优先取执行时快照，后续改名不影响历史记录与对比结论。

4. 编辑器交互

  • 路由 #/plan-editor/{id}（新建用 new）；列表页提供：一键执行 / 预检 / 编辑 / 复制 / 新建。
  • 基础字段：名称、说明、Environment、Executor、AssetSource、fail_fast；下拉只列启用配置，AssetSource 按步骤引擎过滤兼容项。
  • 步骤支持新增 / 删除 / 上移 / 下移，默认串行；引擎仅 pytest/locust/matcheval，切换引擎重置参数。
  • 复制：POST /api/plans/{pid}/copy，副本 rev=1，名称可显式指定（默认「X (副本)」）。
  • 不实现删除计划，避免误删仍被历史引用的计划。
  • PlanRun 详情展示当次 plan_revision 与只读 plan_snapshot。

7. 快照不可变性（验证结论）

  1. 创建计划并执行 → PlanRun 固化 plan_revision=1 + 完整 plan_snapshot + 非敏感指纹。
  2. 随后编辑原计划（改名 / 换步骤 / 关 fail_fast / 换引用）→ 原计划确已变 rev=2。
  3. 重读历史 PlanRun → plan_revision、plan_snapshot 内容、snapshot_fingerprint 全部不变。
  4. 历史 Job config_snapshot 指纹不漂移；执行列表与报告中心计划名取自执行时快照。
