环境与资源配置中心 MVP 实现报告

在三引擎接入、任务控制、报告中心之上，把 pytest / Locust / match_eval 依赖的环境变量、解释器路径、执行机、资产目录与目标服务地址，收敛为平台内受控、可校验、可版本化引用的配置实体。Plan 只引用配置 ID；Job 运行时固化脱敏快照。

只管理 计划/执行/报告/配置 不做鉴权/多租户/分布式调度/用例编辑器 不擅自连接真实 Colyseus/Unity/生产环境 不落明文密钥与绝对路径

1. 配置实体与字段

三类配置实体持久化于独立 SQLite（asset_sources 新表 + environments/executors 增量补列）。前端与 Plan 只提交 ID/key，绝不提交任意命令、路径、Python 可执行文件或素材目录。

Environment（被测环境）

字段含义约束
name名称必填
kind类型受控枚举 http | colyseus | offline
protocol协议受控枚举 http | https
host / port目标地址仅主机名/IP；拒绝路径型与命令片段；offline 免填
secret_ref / secret_kind凭据引用仅环境变量名 / 外部 secret 引用名，不存明文
labels非敏感标签短标识数组（字母数字 _.-）
enabled启用状态停用后不可被 Plan 引用

字段含义约束

enabled启用状态停用后不可被 Plan 引用
python_executable / cwdlegacy 列（迁移兼容）API 一律返回空串，绝不外泄

字段含义受控 key 白名单

ground_truth_ref真值约定fixture-filename | none
airtest_refAirtest 资产目录airtest-master（需用户录入）

Plan / Job 侧：plans 新增 asset_source_id；jobs 新增 config_snapshot。Plan 创建/编辑只接受受控配置 ID 与白名单步骤参数（pytest: args/cwd_root/timeout_sec；locust: locustfile/users/spawn_rate/run_time/csv_full_history/timeout_sec；matcheval: dataset/algorithm/threshold/output_level/timeout_sec），拒绝 command、绝对路径、任意 locustfile/dataset。

2. 迁移策略

  • 增量、非破坏：db.init_db 用 PRAGMA table_info 检测缺失列后 ALTER TABLE ADD COLUMN；新增 asset_sources 表。旧库启动即自动升级，无需重建。
  • 只填空值，绝不覆盖：preset._backfill_config 把旧记录里直存的绝对路径反推为受控引用（infer_interpreter_ref / infer_workdir_root），仅当 python_ref/cwd_root/allowed_runners/asset_source_id 为空时回填。
  • 历史不可变：回填只改 plans/executors 配置行，绝不触碰历史 jobs、reports 与 report.json；历史 Job 缺 config_snapshot 时，索引回退到既有最小环境标识并标 metadata_incomplete=1。
  • 预置幂等：seed_if_empty 按名称幂等创建 Environment/Executor/AssetSource 与演示计划，重复启动不重复插入。

3. 敏感信息处理

密钥

只保存环境变量名或外部 secret reference。API 返回 secret_ref（引用名）+ secret_available（可用/不可用）+ 说明，永不返回值。

路径

mask_path 只保留末段：F:\Anaconda3\python.exe → …/python.exe。执行机/资产视图的 python_executable/cwd 一律置空。

指纹

稳定 sha256 前 12 位，输入仅受控 key 与（文件名,大小）；不含 Token、账号、明文路径。

日志/报告

Job 快照、report.json 环境快照、report_index 只含脱敏视图与指纹；不落密钥值/绝对路径。

验证脚本以已知密钥值 CC_VERIFY_SECRET 为哨兵，断言所有对外响应（catalog / 三类列表 / 单条 / 预检 / 快照 / 报告索引）均不含该值，且不含 F:\、C:\、/usr/、/home/ 等绝对路径特征。

4. 预检结果格式

三类预检统一返回同一结构，只做低风险探测，绝不发起压测或完整测试：

{
  "entity": "environment | executor | asset_source",
  "id": 3, "name": "verify-http",
  "ok": true | false | null,        // null = 无需检查（如 offline 环境）
  "checks": [ { "name": "...", "ok": true|false|null, "detail": "..." } ],
  "missing": [ "TCP 连通性", ... ],  // 失败项名称
  "next_steps": [ "确认目标服务已启动…" ],   // 可行动指引
  "fingerprint": "a1b2c3d4e5f6",     // 资产/环境非敏感指纹
  "dir_fingerprint": "..."           // 资产目录级指纹（仅 matcheval）
}
实体检查项不通过时的指引
Environment类型受控 · 地址已配置 · TCP 连通性（短超时 2s，仅连接不发业务报文）· secret 可用性确认服务已启动、地址端口正确；设置环境变量或外部 secret 引用
Executor解释器引用受控 · 解释器存在 · 版本可读 · 所选 Runner 关键依赖可导入改选可用解释器引用 / 安装缺失依赖（locust、opencv-python+numpy）
AssetSource类型受控 · 引用受控 · 目录/文件存在 · 基础结构完整（可生成非敏感指纹）改选受控 key；确认资产目录已就位且非空；真实资产须用户录入
不误报 Runner 缺陷：缺少 MatchEval 解释器 / Airtest 资产时，返回的是"缺少配置 + 下一步（须用户录入）"，不会把配置缺失包装成 Runner 报错或模拟成功。

5. 前端交互（资源与环境页）

  • 引擎就绪度：三引擎各一行，展示 可运行/缺少配置、可用执行机、缺失项、下一步。仅预检，不发起执行。
  • 三类配置卡片：Environment / Executor / AssetSource 列表 + 新增 / 编辑 / 启停 / 预检。Executor 显示受控引用与脱敏解释器；AssetSource 显示受控 key 与脱敏路径尾。
  • 预检结果面板：✔/✘/○ 逐项 + 缺失项 + 下一步 + 非敏感指纹，就地渲染并滚动定位。
  • 旧环境变量兼容层：展示登记名与"本次进程命中"，标注已弃用并提示迁移。
  • 安全边界：表单只用受控下拉（解释器/工作目录根/dataset/场景），不显示密钥、不提供任意路径浏览器；导航为"资源与环境"。

6. 对旧环境变量的兼容策略

过渡层仍读取旧变量，但已标注弃用，并在 /api/config/catalog 的 deprecated_env 中登记（含"本次进程命中"）。

旧环境变量迁移后的受控解析
PLATFORM_PYTHONExecutor python_ref=anaconda
PLATFORM_LOCUST_PYTHONExecutor python_ref=locust-venv
PLATFORM_MATCHEVAL_PYTHONExecutor python_ref=matcheval（优先能导入 cv2+numpy 的受控候选）
PLATFORM_MATCHEVAL_SCRIPTRunner 固定受控脚本（不随 Job 参数变化）
PLATFORM_AIRTEXT_DIRAssetSource airtest_ref=airtest-master

Runner 只使用后端解析后的受控配置（resolve_runtime_env / resolve_runtime_executor），不信任前端或 DB 中的任意路径/命令。

本轮修复（验证过程中发现并修正）

  • offline 环境预检语义：precheck_environment 对 kind=offline 直接返回 ok=null（无运行时依赖可探测，绝不做任何连接尝试），不再误判为"通过"。
  • 三引擎组合执行机依赖缺陷：原预置把 anaconda-matcheval 声明为可跑 pytest+locust+matcheval，但其解释器（cv2/numpy）并不含 locust，导致三引擎计划的 locust 步骤以 locust exit=1 掩盖配置缺陷。现改为：anaconda-matcheval 只声明 pytest+matcheval；新增专用执行机 three-engine-venv（python_ref=locust-venv，同时具备 pytest+locust+cv2+numpy）承载三引擎组合计划。
