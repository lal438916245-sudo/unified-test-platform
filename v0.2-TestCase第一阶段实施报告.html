4. TestCase API

方法路径请求响应
GET/api/test-casesquery: engine（可选）、enabled=1（可选）TestCase 数组（params/tags 已解析为对象/数组）
GET/api/test-cases/{id}—单个 TestCase；不存在 → 404
POST/api/test-cases{name, description?, engine, params, requires_exclusive?, asset_kind?, owner?, tags?, enabled?}新建的 TestCase（revision=1 + 已计算 fingerprint）；校验失败 → 400
PUT/api/test-cases/{id}同上（整体提交）更新后的 TestCase；仅定义字段变化才 revision+1；校验失败 → 400
POST/api/test-cases/{id}/toggle—切换 enabled（不递增 revision）
DELETE/api/test-cases/{id}—{"deleted": id}；被计划引用时 → 409（附引用它的计划 id 列表）

4.1 校验规则（_tc_errors，与 Plan 步骤共用 validate_step_params）

  • name 必填、≤120 字符、全局唯一（全库无 UNIQUE 约束，沿用应用层校验风格）
  • engine ∈ ENGINES；asset_kind 只能为空或与引擎相容（pytest→''，locust→'locust'，matcheval→'matcheval'）
  • params 键必须命中该引擎白名单；显式拒绝 asset_source_id（属计划/执行级）
  • tags 必须是字符串数组
  • 失败统一返回 HTTP 400，正文为「；」拼接的中文错误（沿用现有格式）

5. fingerprint（两个概念，严格分离）

TestCase
fingerprint= 定义是什么
≠

5.1 定义指纹 test_cases.fingerprint

fingerprint = _h("case", name, engine,
                 json.dumps(params, sort_keys=True, ensure_ascii=False),
                 int(requires_exclusive), asset_kind)

进入：name · engine · params（规范序） · requires_exclusive · asset_kind
不进入：id · description · tags · enabled · owner · revision · created_at · updated_at

复用项目统一 _h()（sha256 截断 12 位），未另造哈希规则。rev 不拼进指纹 —— 二者职责不同。

5.2 内容指纹 Job.config_snapshot.content

content.fingerprint = _h("content", engine, script_fp, asset_dir_fp)

locust    → LOCUST_SCENARIOS[locustfile] 的脚本文件内容 sha256
matcheval → DATASET_REFS[dataset] 派生的 tpl_dir / scenes_dir 的目录内容指纹
pytest    → 不纳入（v0.2 冻结范围，见下）

不纳入：整个项目目录 / WORKDIR_ROOTS（工作目录下既有被测源码又有测试文件，边界不可界定）
        / 解释器环境 / 被测系统全部源码
保护：单文件 > 8MB 降级为 (name,size) 并标 partial；目录条目上限 4000；不落绝对路径
缓存：按（受控 key + 廉价签名）做进程内缓存 —— 同一 PlanRun 内相同 key 只读一次盘

6. revision 规则

事件行为实测
新建revision = 1 + 计算指纹PASS（rev=1）
修改定义字段
（name / engine / params / requires_exclusive / asset_kind）		revision += 1 + 重算指纹PASS（rev 1→2 且指纹变化）
修改 description / tags / owner不递增 revision，指纹不变PASS（rev 保持 1）

Plan 引用存 {id, revision, fingerprint} 三元组PASS
历史 PlanRun不受影响（快照自包含，执行期不回读用例表）PASS

实现方式：不逐字段手写判断，而是比较新旧定义指纹 —— 指纹变了就说明定义变了，天然与 §5.1 的范围一致，不会出现两处规则漂移。

  → HTTP 400，且不产生任何 PlanRun / Job
实测：plan_runs 计数保持 1、jobs 计数保持 1（未因失败请求增加）

10.1 偏差根因（我的失误，已定位）

1) 我在更早的工作里启动过 backend/run.py --no-browser（未设 PLATFORM_DATA_DIR）
   → 该实例的数据目录 = 真实 platform/data，且一直存活占用 8000。
2) 本轮我启动隔离实例时，没有先确认 8000 是否空闲；我的实例打印启动行后因端口被占用而退出，
   而我随后的「8000 状态: UP」探测命中的是那个遗留实例。
3) 于是 verify.py / verify_control.py 打到的是真实库所在的实例 → 追加写入 9 次运行。

教训（已写入项目记忆）：
   · 起隔离实例前必须先 socket 探测目标端口是否空闲；
