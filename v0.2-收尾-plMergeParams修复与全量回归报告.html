2.2 本轮定位到的残留缺陷（"凭空注入默认值"）

规则"原本不存在 + 用户仍用默认值 → 不新增"依赖 PL_DEFAULTED 与表单实际回退值一致。此前两者不一致，守卫因此不触发：

键表单回退值（plStepFields 的 ${p.x??N}）修复前 PL_DEFAULTED后果
timeout_sec（三引擎）300未声明旧步骤凭空多出 timeout_sec:300
locust users51旧步骤凭空多出 users:5
locust spawn_rate21旧步骤凭空多出 spawn_rate:2
matcheval threshold0.8null旧步骤凭空多出 threshold:0.8
为什么这条必须修：注入的默认值会写进 plans.steps，进而改变 plan_snapshot 指纹 —— 与第一阶段"执行即固化、历史不可变"和 v0.2"legacy 逐字节不变"两条不变量直接冲突。
实证手段：前端测试台的合成用例 SYN-missing-defaults（locust 只有 locustfile、matcheval 只有 dataset+algorithm）修复前 失败，修复后 通过。

2.3 一处需说明的语义边界

"用户明确清空 → 删除"只对可以为空的控件成立（args / cwd_root / locustfile / dataset / algorithm）。 数值与带回退的下拉（users / spawn_rate / run_time / timeout_sec / threshold / output_level） 在界面上无法表示"空"，清空会被读成引擎回退值（例如 users 空→按 1 处理）。本轮未改 plReadParams 的该行为 —— 它是既有约定，贸然改动会影响新建步骤的默认值体验。

问题位置影响本轮处置
