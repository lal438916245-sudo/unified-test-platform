一句话结论

平台的功能主流程是完整的：计划 → 预检 → 执行 → 报告 → 产物 → 历史 → 对比，全部有对应页面与接口，且 pytest / matcheval 已在真实资产上跑通并留档。 收尾只差两类东西：① 一份「从启动到跑完一次」的操作文档（含已验收/未验收/已知限制）； ② 一个会让「看日志」这一步不可用的前端轮询缺陷（1 行可修）。 除此之外没有发现阻塞主流程的架构问题。

A. MVP 主流程验收表

步骤功能 / 页面当前状态现有证据用户可能遇到的问题
1 入口：顶栏三入口「测试计划 / 报告中心 / 资源与环境」
`frontend/index.html:63-71`		 已具备 hash 路由 `router()` 覆盖 `#/plans`、`#/reports-center`、`#/env`、`#/run/{id}`、`#/report/{job}`、`#/compare/{b}/{c}`、`#/plan-editor/{id}`；顶栏右侧显示「环境 N · 执行机 N」心跳 三个入口是按功能而非按「被测系统」组织的。平台没有 SUT 实体，用户找不到"我要测 PrivaHigh"这样的入口
2 如何找到/选择被测系统 部分具备 只能通过三条实体间接表达：Environment（跑在哪）+ Executor（用什么解释器/工作目录）+ AssetSource（用什么资产）。AssetSource 列表会显示名称与 kind（如 `privahigh-real · matcheval`） 无「被测系统」概念：用户需要自己去理解"这三条记录合起来才是某个游戏"。AssetSource 名称里带 `privahigh` 是可读性线索，但不是机制保障，也没有分组/标签说明
3 如何确认系统支持的引擎 已具备 `#/env` 页首屏即「引擎就绪度」表：引擎 / 状态（可运行·缺少配置）/ 可用执行机 / 缺失项 / 下一步 —— 数据源 `GET /api/config/readiness` 就绪度在「资源与环境」页，与"建计划"不在同一屏，新手可能直接去建计划而不知道先看这里。另：计划编辑器的引擎下拉是前端硬编码 `PL_ENGINES`，与后端 `ENGINES` 属双源（当前一致）
4 如何配置/选择 Environment · Executor · AssetSource 已具备 三类卡片 + 新增/编辑/停启/预检；表单只提供受控下拉（`catalog` 驱动），含 host 校验、secret 引用名、脱敏展示、secret 可用性徽章；页面底部有约束说明 字段有 placeholder 提示但没有"该选哪个值"的引导（例如 `offline-eval` 该配 kind=offline、跑 locust 该选 kind=colyseus）。AssetSource 在界面上看起来会决定执行内容，实际只在步骤未填参数时作兜底注入（见 B-P1-3）
5 如何运行 Precheck / 理解失败项 已具备 两处入口：计划列表「预检」按钮（已保存）、编辑器「预检 / 执行预览」（草稿，零副作用）。结果含四格就绪标记（引擎已注册/参数合法/执行机允许/依赖就绪）、参数错误列表、三类配置就绪度、锁与全局串行、fail_fast 行为、缺失项、下一步、非敏感指纹 信息量较大但结构清晰；`next_steps`/`missing` 由后端给出可行动文案（如"为对应 Runner 安装缺失依赖…"）。主要问题是没有文档解释这些字段，以及保存失败时提示里带原始 JSON
6 如何创建/选择并执行 Plan 已具备 列表「一键执行/编辑/复制」，编辑器支持步骤增删/上移下移/切引擎重置参数、「保存」「保存并执行」；后端保存时即校验引用与白名单参数（`_plan_errors`） 执行前只有 `confirm('确认触发该计划？')` 一次确认，不显示将要执行的关键参数（闭环报告里"执行前逐项确认"目前是靠人工看预检）。步骤级无"该引擎缺少必填参数"的前端即时校验，要等保存/预检才报
7 如何从运行结果进入报告 / 日志 / 产物 部分具备 执行详情页：状态 chip、尝试次数、退出码、日志、取消、重试、报告链接（仅当 `report_path` 存在）。报告页：指标卡 + 产物下载 + locust/matcheval 专项面板 + 原始 JSON 日志基本不可读：执行详情页的轮询在运行结束后没有 `clearInterval`，整页每 1.2s 重绘一次 → 点开日志后 1~2 秒内容被清空（见 B-P0-2）。另有：报告页的 `plan run N` 是死链（`onclick="return false"`）；pytest 报告看不到失败用例名（需下载 junit.xml 或看日志）
8 如何找到历史运行 / 识别不同次运行 部分具备 两条路：① 计划页「最近执行记录」`GET /api/runs?limit=8`；② 报告中心按 job 维度分页+筛选（计划/引擎/状态/环境/时间），行内显示计划名（取执行时快照）、引擎、环境、开始时间、耗时、关键摘要指标 「最近执行记录」固定 8 条、无分页、无筛选，且这是唯一能看到"没有报告的运行"（如 skipped / cancelled）的地方 —— 一旦被挤出 8 条就查不到。报告中心也无法跳回它所属的 PlanRun（缺少反向导航）

补充：预置计划共 12 个（6 个功能演示 + 6 个 CTRL 任务控制演示，见 `backend/preset.py`），其中需要外部服务端的在名称里已标注「需服务端」/「需服务端 2567」。

B. 阻塞项与非阻塞项

P0 · 不修就无法完成 MVP 主流程或会造成严重误导

#问题证据判断理由
P0-1 缺「从启动到完成一次测试」的操作说明，且 README 与现状矛盾 `README.md` 第 4 行仍写「只接入 `pytest_runner`（独立子进程）」，只列 2 个预置计划；实际已有三引擎、12 个计划、配置中心、报告中心与对比趋势。
`PROJECT_MEMORY.md` 是边界/状态文档，第 33 行「用户尚未授权实际执行」已过时，且无逐步操作指引、无已验收/未验收清单		 MVP 验收项明确包含文档。新用户读 README 会以为平台只支持 pytest，进而找不到三引擎、配置中心与预检的正确用法；"哪些计划不需要被测服务"也没有文档说明，只能靠计划名自己猜。这不是"锦上添花"，而是会导致**第一印象就是错的**
P0-2 执行详情页日志被自动重绘清空（轮询未终止） `frontend/index.html:200-210` `pollRun`：终态判定后仅 `return`，从不 `clearInterval`；`renderRun`（:158）被定时器反复调用并整体替换 `#app`。只有 `router()`（:92）会 `clearInterval` 主流程第 7 步「进入日志」在界面上实际不可用：点「日志」→ 内容出现 → 1.2 秒后被清空，无法阅读滚动。同时整页持续闪动重绘（滚动位置丢失、文本无法选中）。虽不影响报告与产物，但属于主流程内一步不可用，且修复成本仅一行

D. MVP 验收标准（可逐项打勾）

主流程

  • 能按文档启动平台并打开「测试计划 / 报告中心 / 资源与环境」三个页面
  • 能在「资源与环境」看清三引擎就绪状态、缺失项与下一步
  • 能新增/编辑/停启 Environment、Executor、AssetSource，且表单只提供受控下拉
  • 能运行预检，并看懂四格就绪标记、参数错误、缺失项与 next_steps
  • 能新建/编辑/复制计划，步骤可增删排序，切换引擎后参数正确重置
  • 能执行计划，并在执行详情看到状态流转（8 种状态可区分）与退出码
  • 执行结束后日志仍可读（停留 5 秒不被清空）

报告与历史

  • 能从执行详情进入报告，看到指标、产物下载、引擎专项面板与原始 report.json
  • 能在报告中心按计划/引擎/状态/环境/时间筛选并分页
  • 能选取两份报告做一次对比，且不兼容时给出原因说明
  • 能列出 8 条以上的历史运行并定位到某一次（含 skipped/cancelled 的运行）
  • 能从报告跳回其所属 PlanRun

文档与已知限制

  • 有一份「启动到完成一次测试」的简短操作说明
  • 文档列出演示计划及其适用条件（哪些需要外部服务、预期结果是成功还是失败）
  • 文档明确列出已验收能力（pytest 真实功能评估 49 条、matcheval 真实视觉评估 P=R=F1=1.00、报告与配置中心隔离验证）
  • 文档明确列出未验收能力（Locust 真实压测、同一被测系统三引擎闭环、真实数据 A/B 对比）
  • 文档明确列出已知限制（WS 硬编码、动态端口、pytest-html/pymongo 缺口、无依赖清单与绝对路径）

E. 最终判断

结论：只需少量收尾修复

依据

  • 主流程 8 步中 6 步「已具备」、1 步「部分具备（日志被清空）」、1 步「部分具备（历史入口弱）」；没有缺失步骤，也没有架构级缺口。

  • 未把技术债（无依赖清单、绝对路径、死链、提示粗糙等）升级为必须修复项 —— 它们都有明确绕行方式且不阻塞主流程。
